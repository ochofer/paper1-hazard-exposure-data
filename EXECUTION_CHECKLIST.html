C · Panel A — Fama-French factors

Run the download and parse cell

Pulls F-F_Research_Data_Factors_daily_CSV.zip and parses it. Expect a full range starting 1926-07-01 and roughly 25,000+ rows before clipping.

This parser is the one piece already tested. It was run against synthetic files reproducing the real format — preamble, trailing copyright line, missing-value codes, and the annual block that monthly files append. Two genuine bugs were found and fixed that way: a dtype flip to object that would have broken .describe(), and a bare StopIteration on malformed input.
If it fails

ValueError: No YYYYMMDD rows found — the URL is pointing at a monthly file. Monthly dates are six digits and need a different parser plus handling for the annual block. Check the filename contains _daily.

HTTP 404 — French occasionally renames files. Open the data library page and copy the current "Fama/French 3 Factors [Daily]" CSV link.

Timeout or connection error — Dartmouth's server is genuinely slow at times. Just re-run; nothing is cached, so a retry is clean.

Sanity-check the summary table

The window is fixed at 2010-01-01 to 2025-12-31 — set in advance so a rerun on a different day produces an identical file. Expect roughly 4,000 rows.

Values are in percent, not decimals. Mkt-RF = 0.55 means 0.55%. Stored as published, deliberately. Daily Mkt-RF should mostly sit between −3 and +3 with a std near 1. If std is near 0.01, something has already divided by 100 and downstream work will be wrong by two orders of magnitude.

Run the fetch loop and read the misses

22 symbols, ~0.3 s apart, so under a minute. Each prints its row count and date range.

Watch for HTTP 200 but empty payload → counted as MISS. This is the line that matters most. FMP returns a 200 with an empty array for symbols it has no data for, which in aggregate counts looks identical to success. Same convention as your 01_survivorship_test_fmp.py.

If the six .PA / .MI / .L / .DE / .SW tickers all come back empty, your key is almost certainly free-tier — European coverage is a paid feature. That is a plan limit, not a data quality finding, and shouldn't be recorded as one.

Other failure modes

HTTP 401/403 — bad or unauthorised key. Check the secret's notebook-access toggle.

HTTP 429 — rate limited. Raise the time.sleep(0.3) to 1.0 and re-run.

Everything empty including ^GSPC and SPY — the key isn't reaching the API at all. Don't debug ticker by ticker; the problem is authentication.

Only ^GSPC empty — index access is tiered separately on some plans. SPY alone is workable; note the substitution rather than silently dropping the benchmark.
