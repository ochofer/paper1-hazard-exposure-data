A2. Open Terminal and point it at the repo folder YOU

What Terminal is. The Mac app where you type commands instead of clicking. Press Cmd and Space together, type Terminal, press Enter. A window opens with a blinking cursor.

Why it needs pointing at a folder. Terminal is always "inside" one folder at a time, and it starts inside your home folder. Every git command below acts on whatever folder Terminal is currently inside. Skip this and the commands either fail outright or, worse, act on the wrong folder.

The method that avoids typing any path:

#Do this
1Type cd then one space. Do not press Enter yet.
2Open Finder and locate the repo_paper1_data folder, which sits inside Finance Project A.
3Drag that folder out of Finder and drop it onto the Terminal window. Its full path is pasted in for you.
4Now press Enter. The prompt changes to show the folder name.

Terminal is now working inside the repository. You only need to do this once. It stays there for every command in this checklist unless you close the window.

Confirm you landed in the right place before pushing anything. Paste this and press Enter:

git log --oneline && git ls-files

The output has two parts. First a list of commits, most recent at the top, the oldest of which reads Add Paper 1 raw data scaffolding. Then exactly these seven file names:

.gitignore
EXECUTION_CHECKLIST.html
README.md
build_notebook.py

Check the file list, not the number of commits. The commit count varies with how many revisions were made before you started, so it is not something to match against. The seven file names are the reliable signal.

If you see anything else, stop and do not push. Hundreds of files, or the message not a git repository, means Terminal is pointed at the wrong folder. The most likely mistake is landing on Finance Project A itself rather than repo_paper1_data inside it. Redo the drag with the inner folder.

A4. Add the remote and push YOU

"Remote" just means the copy on GitHub. This tells your local folder where to send commits, renames the branch to main, then sends it:

git remote add origin https://github.com/ochofer/paper1-hazard-exposure-data.git
git branch -M main
git push -u origin main

Paste all three lines at once. Success looks like a few lines of counting objects ending in branch 'main' set up to track 'origin/main'.

If the push is rejected

"Updates were rejected" or "non-fast-forward". The remote is not empty, which means a README or licence was created alongside it. Either delete the repository on GitHub and recreate it with nothing ticked, or run git pull --rebase origin main and push again.

"Authentication failed". GitHub no longer accepts account passwords over HTTPS. Create a personal access token in GitHub settings under Developer settings, then use that token as the password. Alternatively switch to SSH with git remote set-url origin git@github.com:ochofer/paper1-hazard-exposure-data.git.

"remote origin already exists". You ran the first line twice. Use git remote set-url origin ... instead of git remote add.

C. Panel A, the Fama-French factors

C1. Run the download and parse cell YOU

Pulls F-F_Research_Data_Factors_daily_CSV.zip from Ken French's library and parses it. Expect a full range starting 1926-07-01 and roughly 25,000 rows before clipping.

This parser is the one piece already tested. It was run against synthetic files reproducing the real format quirks: the copyright preamble, the trailing copyright line, the missing value codes, and the annual block that monthly files append after the monthly rows.

That testing found two genuine bugs, both now fixed. Using pd.NA was silently converting the factor columns to object type, which would have broken the summary table and the magnitude check further down. And malformed input raised a bare StopIteration instead of a readable error.

If it fails

ValueError: No YYYYMMDD rows found. The URL is pointing at a monthly file. Monthly dates are six digits and need a different parser plus handling for the annual block. Check the filename contains _daily.

HTTP 404. French occasionally renames files. Open the data library page and copy the current "Fama/French 3 Factors [Daily]" CSV link.

Timeout or connection error. The Dartmouth server is genuinely slow at times. Just run the cell again; nothing is cached, so a retry is clean.

C2. Sanity check the summary table YOU

The window is fixed at 2010-01-01 to 2025-12-31, set in advance so that a rerun on a different day produces an identical file rather than a quietly longer one. Expect roughly 4,000 rows.

The values are in percent, not decimals. Mkt-RF = 0.55 means 0.55 percent. They are stored exactly as published, deliberately, because the division by 100 belongs in the analysis layer where it can be seen in a diff.

Daily Mkt-RF should sit mostly between minus 3 and plus 3, with a standard deviation near 1. If the standard deviation is near 0.01, something has already divided by 100 and everything downstream will be wrong by two orders of magnitude.
